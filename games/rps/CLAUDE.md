## 한 줄 소개
노을 진 놀이터에서 진행자(챕터 캐릭터)가 가위·바위·보 중 하나를 내밀고, 지령 판의 지령(이겨라·져라·비겨라)에 맞는 내 손을 재빨리 고르는 순발력 게임(약 1분, `abil:'순발력'`). 손 그림은 직접 그린 오리지널 3D 비닐 장난감 질감 장갑 손(공용 `TOY` 필터 재사용, 외곽선 없음).

## 규칙 (플레이어가 보는 것)
- 한 판 = 지령 N개(시간이 아니라 개수로 끝남). 지령마다 **판단 시간(창)** 이 있고, 손과 지령이 "펑" 하고 나온 순간부터 센다. 지령 판 아래쪽 안의 막대가 줄어든다(초록 → 노랑 → 빨강, 남은 0.4초부터 떨림).
- 맞는 손 = 정답, 다른 손 = 오답, 창이 끝나면 시간 초과 오답. **가만히가 정답인 문제는 없다**(아무것도 안 누르면 진다).
- **정답 표**(판정 기준, `tools/rps-judge-test.mjs`가 이 표로 따로 계산해 게임과 맞춰 봄): 가위는 보를, 바위는 가위를, 보는 바위를 이긴다.
  | 지령 | 내야 할 손(상대가 가위일 때 예) |
  |---|---|
  | 이겨라 | 상대를 이기는 손(바위) |
  | 져라 | 상대에게 지는 손(보) |
  | 비겨라 | 상대와 같은 손(가위) |
  | ~하지 마라 | 위 정답 손을 뺀 나머지 두 손 모두 정답(이기지 마라 → 가위·보) |
  | 아까처럼 | 바로 앞 문제의 지령(종류 + 하지 마라 여부)을 그대로, 기준 손은 지금 상대 손. 앞도 "아까처럼"이었으면 그 앞 지령이 이어짐 |
  | 두 손 | 지령 판 위 꼬리표 "◀ 왼쪽 손 / 오른쪽 손 ▶" 쪽 손이 기준(화면에서 왼쪽에 보이는 손 = 왼쪽) |
  | 자리 바꾸기 | 버튼 순서만 바뀜. 판정은 버튼 그림·글자의 손 그대로(키보드 1·2·3도 화면 자리 순서) |
- **한 문제에 판정은 한 번**: 처음 누른 손만 판정하고, 같은 문제에서 그 뒤 누른 것은 무시(두 손가락 동시 누름도 먼저 닿은 것만).
- **손이 나오기 전(준비·주먹 흔들기 중)에 누른 것은 무시**(정답·오답·벌점 없음, 버튼만 살짝 도리도리). 손이 보이기 전에 누르는 것은 찍기라서 받지 않는다. 판단 시간은 손과 지령이 나온 순간부터 세고, 프레임 사이에 누른 것도 누른 시각으로 잰다.
- **틀리면 바로 다음으로**: 판정 연출 0.3초 뒤 다음 손 흔들기(0.4초 안).
- 기회 3개(`.hlives` 별, 하트 아님). 오답마다 1개, 0이면 실패. N개를 다 하면 성공.
- 지령은 늘 **글자 + 메달 그림**: 이겨라 = 초록 꽃 테두리 원 + 왕관, 져라 = 빨강 방패 + 눈물, 비겨라 = 노랑 마름모 + 악수, 아까처럼 = 보라 점선 원 + 되돌이 화살표. 색이 안 보여도 모양·그림·글자로 구분된다(색약 배려). 하지 마라는 메달 위에 검은 금지 표시.
- 진행 리듬: 정답 뒤 0.22초 / 오답 뒤 0.3초 판정 연출 → 주먹 흔들기 0.3초("가위 바위…", 예비 동작) → 손 공개. 이 간격은 판단 시간에 안 들어간다. 오답이면 정답 손에 "정답" 꼬리표가 다음 손이 나올 때까지 남는다.
- 막 누르기: 판정 전·후·흔들기 중에 누른 것은 무시. 0.25초 안에 3번 넘게 누르면 "천천히!" + 0.5초 잠금(벌점 없음, 다만 잠긴 동안에도 판단 시간은 흐름).
- 조작: 엄지 자리 큰 버튼 3개(그림 + 글자, 높이 약 100~142px). 키보드 1·2·3 / A·S·D / ←↓→(화면 순서).
- 콤보: 연속 정답 5·10·20·30에서 "좋아요!/대단해요!/완벽해요!"(점수 영향 없음).
- 진행자 표정: 정답 joy, 오답 sad, 보스 시작 wow(공용 `toySrc` 표정). 판이 끝나면 "평균 판단 0.xx초 · 내 최고 0.xx초(새 기록!)"를 무대에 보여 준다(`store` `hp:rps:best`, 성공 판만 저장).

## 판 만들기
`gen(cfg, rng)`(rng만 씀, 순서 중요): 지령마다 상대 손 `h`(같은 손 세 번 연속 피함) → 두 손이면 `h2`·기준 쪽 `side` → 하지 마라/아까처럼 규칙 문제(`rng`) → 아니면 함정(`rng < trapP`: 져라 60% · 비겨라 40%) → 그림 지령 여부 → 자리 바꾸기 순서(`shuffle`) → 창 길이.
- 창 = `w0 → w1` 선형(한 판 안에서 점점 짧아짐) × 하지 마라 1.15 × 두 손 1.1 × 아까처럼 1.1, 바닥 0.9초.
- 함정 확률 = `cfg.trap × (0.6 + 0.8 × 진행률)`(평균은 trap, 뒤로 갈수록 많아짐).
- 하지 마라: 30% × (0.7 + 0.6 × 진행률), 지령 종류 이겨라 50 · 져라 30 · 비겨라 20. 정답 손 두 개.
- 아까처럼: 26% × 같은 비율(첫 문제 제외). 바로 앞 문제의 지령(종류·하지 마라)을 그대로, 기준 손은 지금 문제 것.
- 같은 씨앗 = 같은 손·같은 지령·같은 버튼 순서·같은 창(점검: `NG.rps._test.sig()`).

## 모드별 동작
**오늘의 문제·연습·대전**(`levels`, `limit:0`):

| 난이도 | 지령 | 판단 창 | 함정 | 진행자·노을 |
|---|---|---|---|---|
| easy | 20개 | 2.6 → 2.0초 | 15% | 강아지 · 골목 |
| normal | 25개 | 2.2 → 1.5초 | 25% | 고양이 · 놀이공원 |
| hard | 30개 | 1.9 → 1.2초 | 35% | 호랑이 · 왕좌 |

오늘의 시험지 과목(`SUBJ`)에는 아직 넣지 않음(사용자 확인 후).

**솔로**(`stageCfg(n)`, 개념 사이클 `planOf('rps', n)`, 개념 표 `CONC`):

| 스테이지 | 종류 | 이름(key) | 내용 |
|---|---|---|---|
| 6 | 변주 | 빠른 판(flash) | 창 ×0.85 |
| 11 | 새 규칙 | 그림 지령(hide) | 60% 문제에서 글자 없이 메달만 |
| 16 | 변주 | 자리 바꾸기(swap) | 내 손 버튼 순서가 지령마다 섞임(흔들기 때 미리 바뀜) |
| 21 | 새 규칙 | 하지 마라(not) | "이기지 마라" 등, 맞는 손 두 개 |
| 26 | 변주 | 외줄 타기(tight) | 기회 2개 |
| 31 | 새 규칙 | 두 손(two) | 55% 문제에서 두 손, 지령 판 꼬리표 "◀ 왼쪽 손 / 오른쪽 손 ▶" 쪽이 기준 |
| 41 | 새 규칙 | 아까처럼(last) | 앞 문제 지령을 기억해서 적용 |

- 지령 수: 12 + 2×(챕터−1) + round((k−1)×6/8)(k=1~9), 보스 = 챕터 기본 + 12, 최대 32.
- 창: 2.7 → 2.1초 × 0.94^(챕터−1)(12챕터까지) × 자리 배수(k=5 0.9 · 보스 0.85 · 쉬어가기 1.15 · 소개 판 1.08) × 빠른 판 0.85, 시작 최소 1.1 · 끝 최소 0.9초.
- 함정: 10% + 7.5%p×(챕터−1)(최대 45%), 보스 +10%p, 쉬운 판(k 1·6·9) −5%p.
- 챕터: 골목 대결(강아지) · 운동장(고양이) · 놀이공원(곰) · 지령 본부(토끼) · 가위바위보 왕좌(호랑이). 챕터마다 노을 빛(`PAL`)·진행자 말투(`HOST_LINE`)·소매 색이 바뀜. 대장 판은 빨간 "대장 판!" 띠 + 붉은 빛 + 진행자 wow.
- **아직 플레이 데이터로 맞추지 않은 첫 값.**

**별**: 오답 0 → ★★★, 1 → ★★, 그 외 ★.

**대전**: normal(25개) 같은 씨앗 = 같은 지령, **모두 끝났을 때 점수 높은 쪽 승**(대전 v3 `duelKind:'score'`, `duelEnd:'all'`, 1:1 `duelMax:2`). 대전 v3 기본값(경주: 먼저 끝낸 사람 1등, 0.7초 뒤 모두 끝)이면 실수가 많아도 빨리 끝낸 쪽이 이기고 늦은 사람이 잘려서 점수전으로 맞춤.
- `duelStat = { unit:'점', score:true, lfMax:3, v:지금까지 점수(정답 500 + 판단 속도 350 부분, 배율 전), t:N, lf:남은 기회, mis:틀린 수 }`.
- 순위 `duelRank`: 둘 다 끝났으면 성공한 사람이 앞, 둘 다 성공이면 결과 점수(남은 기회 포함) 높은 쪽. 그 밖은 엔진 기본(v → 틀린 수).
- 컴퓨터 상대 `duelAi`: 성공 75%, 같은 점수 눈금(`pts` = 정답 비율·속도로 계산, `sc` = pts + 50×남은 기회), 시간 `duelPace:[55,.75]` 기준. 대전은 늘 기회 3개. 대전 중 엔진은 멈추지 않으므로 게임 시계(`m.t`)는 `G.paused`(시작 카운트다운 동안만 참)일 때만 멈춘다.

## 점수 (배율 전 최대 1,000)
- base = 500 × 정답 수 / N
- time = 350 × (지령마다 남은 창 비율의 합 / N), 오답·시간 초과는 0
- extra = 50 × 남은 기회(최대 150)
- 결과 줄: `정답 a/N` · `판단 속도 보너스 (평균 0.xx초)` · `남은 기회 n개`
- 점검(`tools/rps-judge-test.mjs` 3절): 0.3초에 정답만 누르는 봇 → 성공·900점 이상(배율 전), 마구 누르기 봇 → 실패, 아무것도 안 누르기 봇 → 실패.

## 고칠 때 지킬 것
- 문제 내용은 **rng로만**. `gen`의 rng 쓰는 순서를 바꾸면 같은 씨앗의 문제가 달라진다(새 항목은 끝에).
- 시계는 `m.t`(requestAnimationFrame 누적, `G.paused`면 멈춤). `setTimeout`은 연출·끝내기에만(`T()`로 등록해 `G.cleanup`에서 지움).
- 화면은 `transform`·`opacity`만 움직인다(60fps). 효과는 `try{}catch(_){}`(`fx()`), 눌림을 막지 않게 `pointer-events:none`. 동작 줄이기면 흔들기·파티클 생략.
- 버튼은 화면 아래(엄지 자리), 높이 92px 이상. 390×844·360×740에서 스크롤 없이 들어가야 한다(`layout()`이 높이를 맞춤, `.wrap` 아래 여백 8px).
- 화면 구성: 무대(진행자 위 · 상대 손 가운데 · 내 손이 아래에서 올라와 맞부딪힘) → 지령 판이 무대 아래를 `--cover`(20px)만큼 덮는 간판(메달이 판 위로 살짝 튀어나옴, 판단 막대는 판 아래 테두리 안쪽) → 버튼 3개. 판정을 고치면 `node tools/rps-judge-test.mjs`를 꼭 돌린다.
- 지령은 색 + 모양 + 글자 셋 다 다르게. 새 지령을 더하면 메달 모양도 새로.
- 새 문구에 대시(—, –) 쓰지 않기. 그림·이름은 오리지널만(docs/13_법무검토_IP.md).
