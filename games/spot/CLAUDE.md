## 한 줄 소개
저작권이 끝난 명화 40점(보티첼리·다 빈치·페르메이르·고흐·모네·클림트·호쿠사이·김홍도·신윤복·정선 …)을 위아래 두 장으로 놓고, 아래 그림에서 달라진 곳 N곳을 찾아 누르는 집중력 게임(약 2분). 끝나면 그 명화의 작품명·작가·연도·소장처·쉬운 설명을 결과 창에 보여 준다(`resultNote`). 직접 그린 장면(그림 조각 61종·테마 8개)은 2026-10-10에 모두 지웠다(옛 코드는 git 기록에만 있음).

## 규칙 (플레이어가 보는 것)
- 위 그림(원래)·아래 그림(차이 있음) **어느 쪽을 눌러도** 판정. 찾으면 두 그림 모두에 분홍 동그라미(진한 외곽 + 흰 바깥선 + 분홍 4.4, 휴대폰에서 약 4px).
- 차이 동그라미 반지름 + 7(그림 단위, `TOL`) 안을 누르면 찾은 것. 이미 찾은 곳을 다시 누르면 아무 일 없음.
- **빗나감** = 차이가 없는 곳을 누름 → 점수 −15(`MISS_PTS`), 잠깐 누를 수 없음. 연출은 약하게: 판을 흐리게 하지 않고 누른 자리에 ×, 누른 그림만 0.3초 살짝 흔들림, 정보줄 오른쪽 칩에 "잠깐! 0.6초"(14px)와 줄어드는 막대(`coolShow`, 루트 `.ng-spot.cool`)(0.7초, 연달아 빗나갈수록 +0.4초, 최대 2.4초). 기본은 기회 제한 없음. 외줄 타기 변주만 기회 2번(두 번째 빗나감에서 끝). 대전은 늘 기회 제한 없음.
- 💡 힌트: 못 찾은 차이 하나의 **근처**를 큰 점선 동그라미로 2.8초 보여 줌(정확한 자리는 아님). 판마다 3번(보스 2, 맨손 0), 점수 −40(`HINT_PTS`).
- 제한 시간 안에 모두 찾으면 성공. 실패하면 못 찾은 곳을 노란 점선 동그라미로 보여 준다.

## 판 만들기 (모든 판은 N곳을 반드시 찾을 수 있음)
`gen(cfg, rng)` → `masterGen`(rng만 씀):
1. 그림 고르기: `cfg.theme`(그림 id `m01`~`m40`)이 있으면 그것, 없으면 rng로 40점 중에서 `cfg.avoid`(최근 본 그림)를 뺀 목록에서. 오늘의 문제는 `init`에서 차이 수×7번 rng를 넘겨 같은 날이라도 난이도마다 다른 그림.
2. 그 작품의 차이 12곳(`SPOT_MASTERS`)을 rng로 섞어 **N곳만** 고른다(살금살금 변주는 '색 바꾸기·밝기 바꾸기' 우선). 고르지 않은 곳은 원본 그대로라서 N이 5·7·9·12 무엇이든 위·아래가 정확히 N곳만 다르다.
3. 그림을 320×240 판 안에 **비율을 지켜**(남는 곳은 진한 보라) 놓고, 차이 좌표·반지름(긴 변×0.042~0.060, 최소 14)을 판 좌표로 바꾼다. 차이끼리는 도구가 만들 때 이미 겹치지 않는다.
4. 아래 그림 = 위 그림 + 고른 차이 조각(`<image>`)을 얹은 것. 그림 파일은 `init`에서 미리 불러오고(`m.imgs`), 다 불러와야 시계가 시작한다(최대 9초).
- 차이 종류(도구가 만듦): 색 바꾸기 · 밝기 바꾸기 · 색 섞기 · 뒤집기 · 돌리기 · 바꿔치기(다른 자리 조각). 평균 변화량이 기준(15→12→10) 이상인 것만.
- 점검(2026-10-10): 40점 × 차이 5·7·9·12 × 살금살금 2 × 씨앗 3 = 960판 — 개수 틀림 0·그림 밖 0·동그라미 겹침 0, 솔로 1~60판 실패 0, 같은 씨앗 = 같은 그림·같은 차이.

## 모드별 동작
**오늘의 문제·연습·대전**(`levels`):

| 난이도 | 차이 | 제한 시간 | 힌트 |
|---|---|---|---|
| easy | 5곳 | 120초 | 3 |
| normal | 7곳 | 150초 | 3 |
| hard | 9곳 | 180초 | 3 |

오늘의 시험지 과목(`SUBJ`)에는 아직 넣지 않음(넣는다면 '집중' 과목 제안). 연습은 배율 0.6/1.0/1.4.

**솔로**(`stageCfg(n)`, 개념 사이클 `planOf('spot', n)`, 개념 표 `CONC`):

| 스테이지 | 종류 | 이름(key) | 내용 |
|---|---|---|---|
| 6 | 변주 | 빠른 판(flash) | 시간 ×0.65 |
| 11 | 새 규칙 | 거울 그림(mirror) | 아래 그림 좌우 반전(`matrix(-1 0 0 1 W 0)`), 누른 자리도 거꾸로 계산 |
| 16 | 변주 | 맨손(bare) | 힌트 0 |
| 21 | 새 규칙 | 깜빡 커튼(blink) | 5초마다 3.2초 보이고 1.8초 한쪽 그림이 커튼에 가려짐(위·아래 번갈아). 가려진 그림은 못 누름(벌칙 없음) |
| 26 | 변주 | 외줄 타기(tight) | 기회 2번(두 번째 빗나감에서 끝) |
| 36 | 변주 | 살금살금(subtle) | 색·밝기가 바뀐 차이를 우선, 시간 ×1.25 |
| 31 | 새 규칙 | 몇 곳일까?(secret) | 차이 수를 숨김(`/?곳`), 다 찾으면 저절로 끝 |
| 46 | 변주 | 차이 잔치(more) | 차이 +2곳 |

- 사이클 자리 k: 1 소개(쉬움) · 5 어려움 · 6 변주 소개 · 9 쉬어가기 · 10 보스. 51부터 리믹스.
- 차이 수: 챕터 1 = `LT.ch1[k−1]`(4·5·5·5·6·4·5·6·4·7), 챕터 2~ = `LT.base[c] + LT.kOff[k]`(기본 6·6·7·7·8), 3~12곳.
- 제한 시간 = 차이 × `LT.spp[c]`(22·20·19·18·17·16초) × `kTime[k]` × 규칙 배수(`mjTime`: 거울 1.15·커튼 1.25·비밀 1.1) × 변주 배수(`twTime`), 5초 단위, 최소 40초. **아직 플레이 데이터로 맞추지 않은 첫 값.**
- 그림 = `TL[(n − 1 + c) % TL.length]`, `TL` = 명화 id 40개(스테이지마다 다른 명화, 60판 동안 39점 등장). 개념 사이클은 새 규칙이 3개(거울·깜빡 커튼·몇 곳일까)라 51판부터가 아니라 41판부터 리믹스.
- 챕터 이름: 눈 크게 뜨기 · 반짝 관찰단 · 숨바꼭질 골목 · 매의 눈 · 명탐정의 방.

**별**: 힌트+빗나감 0 → ★★★, 2 이하 → ★★, 그 외 ★.

**대전(v1.2 선점, 2~5명)**: `duelCfg` = 보통 + 차이 7곳·90초·힌트 1(느긋하게 180초). 먼저 누른 사람이 `duelClaim('d'+i)`로 차지(주인은 엔진), 표시는 `onDuelClaim` → `claimSeen`(자리 색·모양 `ownRing`, 이름표 `claimTag`). 끝 = 다 차지 또는 1위를 못 따라잡음(`sharedEndCheck`) → `duelEndNow`. 순위 = 차지 수 → 실수 → 마지막 차지 시각. 점검용 `_tapDiffForTest(i)`·`_tapMissForTest()`. (아래는 v1.1 경주 기록) `duelStat = { unit:'곳', v:찾은 곳, t:전체, mis:빗나감 }`, 기회 제한 없음, 몇 곳일까 규칙 꺼짐. `duelPace:[85,.8]`, `duelHow:'같은 그림 · 누가 먼저 차이를 다 찾나'`.
- **다시 붙어도 다른 그림**(`duelTheme`): 그림은 명화 40점 중 rng로 고르되 ① 판 번호만큼 rng를 13번씩 넘기고 ② 최근 그림 2점을 뺀다. 판 번호·피할 목록은 공용 대전 v3가 주면(`G.duel.round`, `duelCfg({ avoid })` → `cfg.avoid`) 그것을, 지금(v2)은 이 페이지에서 같은 대전 씨앗을 만난 차례(`DUEL_SEEN[씨앗]`, 같은 두 사람이 같은 연결로 다시 붙으면 씨앗이 같음)와 그 씨앗에서 나온 최근 테마 2개를 쓴다 → 두 기기가 같은 차례로 같은 씨앗을 만나므로 늘 같은 그림. 컴퓨터 대전은 내 기기에서 최근 본 테마(`hp:spot:duelSeen`) 2개를 더 피함.
- v3 계약 칸: `duelAvoidKey() = 지금 그림 id`, `duelCfg(o) = levels.normal + avoid`(rng 안 씀).

## 점수
엔진 `calcScore()` = round((base + time + extra) × 배율). `score()`:
- base 500
- time = max(0, 350 − floor(sec × 350 / 제한 시간))
- extra = max(0, 150 − 40×힌트 − 15×빗나감)

## 고칠 때 지킬 것
- 장면·차이는 **주어진 rng에서만**(Math.random 금지, 효과 연출 제외). 힌트 자리는 `m.rng`(판을 만든 뒤 이어 쓰는 rng).
- 명화 목록(`spot-masters.js`)과 `art/` 파일은 **손으로 고치지 않고** `python3 -I tools/masterpiece/export.py --game --diffs 12 --out games/spot`으로 다시 만든다. 작품 순서·`diffs` 순서·`export.py`의 씨앗을 바꾸면 같은 씨앗의 그림·차이가 달라진다(작품 추가는 끝에).
- **저작권**: 작가가 1955년 이전에 사망한 작품만, 원본은 위키미디어 공용에서 라이선스가 공공 영역(PD)/CC0인 파일만(`export.py`가 자동으로 거름). 출처·라이선스는 `out/masterpiece/CREDITS.md`와 `answers.json`에 남는다. 규칙 전체: `docs/23_명화_틀린그림_저작권.md`.
- 작품 설명(`tools/masterpiece/catalog.json`의 `desc`·`place`)은 **실제 쓴 파일과 맞는지** 확인한다(소장처가 확실하지 않으면 중립 표기).
- 차이 반지름·좌표를 바꾸면 위 생성 점검을 다시 돌린다(개수·겹침·그림 밖·최소 14).
- 아래 그림의 동그라미는 `<use>` 복사본으로 보이므로 CSS 애니메이션이 안 걸린다(속성으로만 그림). 효과는 `try{}catch(_){}`로 감싼다.
- CSS는 `css` 문자열 안에만, `.ng-spot` / `body[data-mode="spot"]`로 범위를 묶는다(키프레임 `spot-…`).
- 게임 이름·화면·문구는 오리지널만. 그림은 공공 영역 명화만(상용 게임·캐릭터 그림 금지).

## 확인 방법
- `node tools/build.js` → index.html 목록과 `embed/spot.html` 다시 만들기.
