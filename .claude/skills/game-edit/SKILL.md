# 게임 하나 고치기

1. **어느 게임인지 정하기**: fox(여우 자리 찾기) sudoku(스도쿠) ball(별빛 구슬) tower(숲 지킴이) fleet(함대 결전) match(동물 삼총사) nono(네모 그림) block(블록 채우기) memory(카드 짝 맞추기) merge(숫자 합치기). 애매하면 사용자에게 묻는다.
2. **게임 프롬프트 읽기**: `games/<id>/CLAUDE.md` 전체, 특히 **사용자 지시**. 지시와 요청이 부딪히면 사용자에게 먼저 묻는다.
3. **지시만 남기는 요청**("앞으로 ~하게", "프롬프트에 적어 둬")이면 `사용자 지시` 맨 위에 `- YYYY-MM-DD 내용`으로 적고 끝.
4. **고치기**: 그 게임 폴더(`games/<id>/`) 안에서만. 공용(`core/`)을 고쳐야 하면 이유를 사용자에게 말하고 모든 게임을 점검한다. 규칙: 문제 내용은 rng로만, 게임 정의 `NG.<id>` 계약(`games/CLAUDE.md`) 유지, 오리지널 그림·이름만.
5. **빌드·점검**: `node tools/build.js` → `npm test -- <id>`(필요하면 전체 `npm test`). 화면을 바꿨으면 390px 폭에서 `index.html`과 `embed/<id>.html?mode=menu`를 직접 열어 본다. 난이도를 바꿨으면 그 게임 CLAUDE.md의 확인 방법(난이도 도구)도 돌린다.
6. **기록**: `games/<id>/CLAUDE.md`의 **바뀐 기록**에 날짜와 한 줄, 숫자·규칙이 바뀌었으면 그 표도 고친다. 동작이 바뀌면 `game.json`의 `version`을 올린다.
7. **올리기**: 사용자가 바로 반영을 원하면 커밋·푸시(main → GitHub Pages). 커밋 메시지는 "<게임 이름>: 무엇을" 형식.
8. **답하기**: 무엇을 바꿨는지, 사이트·모듈 어디에 반영되는지 한국어로 짧게.
