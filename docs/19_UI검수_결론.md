## 총평 (3줄)

1. 사이트(오늘·솔로·대전·리그·내 정보)는 "밤하늘 광장 + 양피지 패널 + 사탕 버튼" 세계가 잘 잡혀 있고 캐릭터·카드 그림 품질도 높다. 브랜드는 이미 완성 단계다.
2. 문제는 **게임 화면 쪽의 통일성**이다. 상단 정보줄(HUD)이 최소 6가지 모양(복사해 붙인 칩 11벌 + 크림 막대 + 진한 패널 + 상자 3개 + 캐릭터 패널 + 함대 전용)으로 갈라져 있고, 도구 버튼 색이 의미 없이 무지개이며, 판 아래가 150~190px씩 비는 게임이 많다.
3. 바로 고쳐야 할 것은 4가지다: **결과 창을 덮는 꽃가루**, **고스톱 19세 확인 창이 90° 누워 있음**, **버튼 6개짜리 결과 창**, **30대 이상에게 작고 흐린 글자**(12px 이하·대비 4.5:1 미달).

## 문제 목록 (우선순위순, 22개)

### P0: 출시 전 꼭

**1. [결과 창(성공)] 꽃가루가 제목·점수·버튼을 덮음**
- 문제: "클리어!" 글자, "500", "점수 자세히", "다음 게임" 버튼 위로 색종이가 지나간다(06_result_win). 원인은 효과 캔버스 `.fxfx{z-index:30}`가 팝업 `.veil{z-index:20}`보다 위에 있기 때문.
- 해결: 결과 창이 열려 있을 땐 효과를 창 **뒤**로 보낸다. `.veil.on ~ .fxfx, body.modal-open .fxfx{z-index:19}` (또는 `.fxfx{z-index:19}`로 고정하고 판 위 효과만 쓰는 경우는 그대로). 꽃가루는 1.2초 안에 끝나게, 창 위쪽 30% 영역에서만 터지게. `prefers-reduced-motion`이면 꽃가루 생략.
- 파일: `core/effects.css` `.fxfx`, `core/effects-sound.js`(꽃가루 호출부). 공용 엔진 수정이므로 `npm run test:duel` 필요(효과는 보이기만, 눌림 막지 않음 유지).

**2. [고스톱 첫 화면] 19세 확인 창이 옆으로 누워 있음**
- 문제: 세로 폰에서 판 전체를 90° 돌리는데(`fit()`의 `rotate(90deg)`), 나이 확인 창도 판 안에 있어서 글자·버튼이 옆으로 누운 채 나온다(g_gostop). 30대 이상 사용자가 첫 화면에서 고개를 꺾어 읽어야 하고, "아니요/네" 위치도 헷갈린다.
- 해결: 나이 확인·시작 전 안내 창은 `#gsb` 밖(공용 `.veil .modal`)으로 빼서 **항상 똑바로** 띄운다. 판이 돌아가는 상태라면 확인 뒤에 "휴대폰을 옆으로 눕혀 주세요" 그림 안내(1.5초)를 한 번 보여 준다. 버튼은 공용 `.mbtns` 규격(높이 54px, 왼쪽 파랑 "아니요", 오른쪽 핑크 "네, 만 19세 이상이에요").
- 파일: `games/gostop/gostop.js` `fit()`(357줄 부근)과 나이 확인 창 그리는 곳, `games/gostop/gostop.css`. 게임 폴더만 수정.

**3. [결과 창(성공)] 할 일이 너무 많고 버튼 글자가 넘침**
- 문제: 한 창에 알약 3개(과목 등급·출석·친구 순위) + "점수 자세히" + 버튼 5개(도전장·결과 카드 공유·같은 문제 연습·다음 게임·홈으로). 버튼 색도 핑크·노랑·파랑·핑크로 섞여 무엇을 누를지 안 보인다. "다음 게임: 네모 그림"은 `white-space:nowrap` 때문에 버튼 테두리에 붙어 잘린다.
- 해결(위계 3단):
  - 1순위 큰 버튼 1개(핑크, 전체 폭, 높이 56px): **"다음 과목 풀기"** (아래 작은 줄에 "네모 그림" 13px).
  - 2순위 반반 2개(높이 48px): 파랑 "같은 문제 연습 ♥1" · 노랑 "친구에게 도전장".
  - 3순위 글자 버튼 1줄(높이 44px, 버튼 아님): "결과 카드 공유 · 홈으로".
  - 알약 3개는 1개 묶음 카드로: `집중 미 · 상위 42.5%` 를 큰 글씨(17px)로, 출석·친구 순위는 그 아래 13px 한 줄.
  - 긴 이름 대비: `.mbtns button{white-space:normal; line-height:1.15}` + 버튼 안 보조 줄 `small{display:block; font-size:12.5px}`.
- 파일: `core/engine.js`(결과 창 마크업), `core/base.css` `.mbtns`·`.pill`. 이벤트 이름·필드는 바꾸지 않고 배치만 바꿈.

**4. [전체] 글자 대비(WCAG) 미달 구간**
- 측정 결과(4.5:1이 작은 글자 기준):
  - 홈 CTA 위 작은 줄 "다음 과목 · 어려움" `#FFF1A8` on 핑크 = **2.69:1** (12.5px) → 실패.
  - 보조 글자 `--sub #7B6A93` on `--paper2 #FBEBCB` = **4.13:1** (12~13px에서 실패, 패널 아래쪽 그라데이션 구간).
  - 동물 삼총사 제목 아래 줄 `#6B7197` on 하늘색 = **3.81:1** (11px).
  - 리그 "예시" 꼬리표 `#9C7A1F` on `#FFF0C2` = 3.55:1 (11px).
  - 출석 요일 `.wd` `#B7A27A` on `#EFE3CB` = 1.95:1, 꺼진 별 `#D8C8A8` on 크림 = 1.56:1.
- 해결:
  - `--sub: #6A5884` (paper 5.94 / paper2 5.34:1). 한 줄만 바꾸면 사이트·모듈 전체가 올라감.
  - `.cta-txt i{color:#fff; text-shadow:0 1px 0 #8E0F4F; font-size:13px}` 또는 글자 뒤에 `background:rgba(120,0,60,.35); padding:1px 8px; border-radius:99px` 알약.
  - 동물 삼총사 부제목 `#4A4F7A`, 11px → 12.5px.
  - `.row .samp{color:#7A5A00}`, `.wd{color:#8F7A52}`.
  - 꺼진 별·잠금은 "꺼짐"이 의미라 대비는 3:1까지 허용: `.st i .off{color:#BFAE8A}`, `.st.lock{color:#8F7C55}`.
- 파일: `core/base.css` `:root`, `core/base.css` `.cta-txt i`, `games/match/match.js` `.mt-ttl small`, `portal/portal.css` `.row .samp`·`.wd`, `core/play.css` `.st`.

### P1: 다음 묶음에서

**5. [게임 20개] 상단 정보줄(HUD) 모양이 6가지로 갈라짐**
- 현황:
  - A형 알약 칩: chosung·crossword·hidden·link·memory·mines·nono·omok·parking·spot·wordchain (11개). 그런데 `cs-chip`, `cw-chip`, `lk-chip`, `mn-chip`, `sp-chip`… 게임마다 **같은 CSS를 복사**해서 글자색·폭이 조금씩 다름(13.5px/12px 섞임).
  - B형 크림 막대(라벨 위·숫자 아래 + 보라 일시정지): sudoku·fox·ball.
  - C형 진한 패널(목표 512 타일 + 4칸): merge.
  - D형 크림 상자 3개(진행 막대 포함): block.
  - E형 캐릭터 얼굴 + 목표 + 남은 이동: match.
  - F형 작은 칩 3개 + 해 막대: tower. G형 함대 전용 바다색: fleet.
- 해결: core에 **게임 이름을 모르는 공용 칩 규격** `.hchip`을 하나 두고, 게임은 `NG.<id>.hud`(선택 항목)로 칩 목록만 넘긴다. 규격은 아래 "HUD 칩 규격" 참고. 순서 규칙: ① 진행(0/15) ② 시간 ③ 힌트(노랑) ④ 넘기기·섞기(하늘). 칩은 최대 4개, 그 이상은 판 위 보조 줄로.
  - B형(스도쿠·여우·구슬)도 칩으로 맞추되 "실수" 표시만 칩 안 동그라미 3개로 유지. 일시정지는 칩 줄 맨 오른쪽 44×44 `.iconbtn`(대전 중엔 숨김, 기존 규칙 유지).
  - C·D·E형(merge·block·match)은 게임 성격상 "목표 진행"이 핵심이라 큰 패널을 써도 되지만 테두리·모서리·그림자는 칩 규격과 같은 토큰 사용(`border:2.5px solid #1A0F45; border-radius:18px; box-shadow:0 3px 0 #1A0F45`).
- 파일: `core/play.css`(새 `.hchip`), `core/engine.js`(선택 항목 읽기), 각 `games/<id>/<id>.js`의 `xx-chip`·`xx-hud`. core 수정이므로 전 게임 점검 + 사용자에게 "공용 엔진을 고쳤다" 보고.

**6. [동물 삼총사·함대 결전] 맨 위 제목 막대가 공용과 다름**
- 문제: 다른 18개 게임은 보라 알약 제목 막대(`.pbar`: 흰 동그라미 ← / ?)인데, 동물 삼총사는 막대 없이 회색 글자 제목(`#3F4470`), 함대 결전은 테두리만 있는 어두운 원 버튼 + 얇은 화살표 + 민트 "출격!" 버튼 + 일반 글꼴. 다른 회사 앱처럼 보인다. 함대는 세로 줄 번호 "10"이 판 왼쪽에서 "1("로 잘림.
- 해결: 두 게임 모두 `.pbar` 그대로 사용(배경 테마는 유지: 하늘 거품·밤바다 OK). 함대 "출격!"은 공용 핑크 사탕 `.btn.primary`, "무작위"는 `.btn.secondary`. 줄 번호 칸 폭 `min-width:22px; text-align:right; padding-right:4px`. 함대 보조 글자 `#8DB4D4`는 남색 배경에서 OK(대비 7:1 이상).
- 파일: `games/match/match.js`(`.mt-top`·`.mt-ttl`), `games/fleet/fleet.css`(`.fl-top`, 출격 버튼, 행 라벨).

**7. [스도쿠·블록·네모 그림·초성·여우·숫자 합치기] 판 아래가 150~190px 비어 있음**
- 문제: 판은 위에 붙고 버튼 줄도 판 바로 아래에 붙어서, 화면 아래 1/4이 무늬 배경만 남는다(05_play_sudoku, g_block, g_nono, g_chosung, g_fox, g_merge). 엄지가 닿는 아래쪽이 비고 정작 누를 숫자판은 화면 가운데에 있다.
- 해결(우선순위대로):
  1. 판 크기를 화면 높이 기준으로 키운다: `--board: min(calc(100vw - 32px), calc(100dvh - var(--hud-h) - var(--ctrl-h) - 48px - env(safe-area-inset-bottom)))`.
  2. 플레이 화면을 세로 흐름으로: `#play{display:flex; flex-direction:column; min-height:100dvh}` + 조작 줄 `margin-top:auto; padding-bottom:calc(12px + env(safe-area-inset-bottom))` → 숫자판·조각 트레이가 **엄지 자리(아래)** 로 내려감.
  3. 남는 공간이 있으면 판과 조작 줄 사이 간격만 `clamp(12px, 3dvh, 28px)`로 늘린다. 장식 캐릭터로 채우지 않는다.
  - 스도쿠 숫자 키는 높이 52px → `min(64px, 9dvh)`로(30대 이상 손가락).
- 파일: 각 게임 폴더 CSS(`games/sudoku/sudoku.css`, block·nono·chosung·fox·merge의 JS 안 CSS). 공용으로 하고 싶으면 `NG.<id>.layout:'fill'` 선택 항목.

**8. [게임 도구 버튼] 색이 의미 없이 무지개**
- 문제: 스도쿠 하단 4개가 보라(되돌리기)·핑크(지우기)·파랑(메모)·노랑(힌트). 여우는 노랑·파랑·회색, 구슬은 핑크·파랑·초록, 주차는 크림 글자 버튼. 같은 "되돌리기"가 게임마다 다른 색.
- 해결: 도구 버튼 3종으로 고정.
  - **보통 도구**(되돌리기·지우기·처음부터·표시): 크림 `background:linear-gradient(#FFFFFF,#F3EBDD); border:2.5px solid #1A0F45; color:#3A2261; box-shadow:0 3px 0 #1A0F45`.
  - **켜고 끄는 도구**(메모·칠하기/표시): 꺼짐=보통 도구, 켜짐=보라 사탕(`--c1:#A98BFF; --c2:#6C3CE0; --c3:#3A1A8F`) + "ON" 표시.
  - **아이템**(힌트·자동·관통 등 개수 있는 것): 노랑 사탕 `.btn.gold` + 오른쪽 위 숫자 배지.
  - 핑크는 "시작·발사·확인" 같은 **주 행동 1개**에만.
- 파일: 각 게임 JS 안 도구 버튼 CSS. core에 `.tool`, `.tool.toggle[aria-pressed=true]`, `.tool.item` 3개 클래스 추가하면 복사가 줄어듦.

**9. [전체] 30대 이상에게 작은 글자**
- 문제: 12px 이하가 곳곳에 있다. `.ptitle small` 11.5px(게임 막대 부제목), 칩 12px(link·mines·spot 좁은 화면), `.db-val small` 10.5px, `.bdg` 10.5px(배지 이름), `.newb` 10px(홈 NEW), `.mt-ttl small` 11px, 대전 `.aitag` 10px, 네모 그림 단서 숫자(15×15에서 약 11px). 회색 설명문 12~12.5px도 많다.
- 해결: 최소 크기 규칙 **본문 15px · 보조 13px · 숫자 꼬리표 12px(굵게)**. 구체값: `.ptitle small{font-size:12.5px}`, 칩 값 18~20px·단위 13px, `.bdg{font-size:12px}`, `.gr-mid span{font-size:13px}`, `.hstep span{font-size:15px; line-height:1.55}`(도움말은 읽는 글), 네모 그림 단서는 `--f`의 최저값을 12px로 막고 15×15 이상이면 단서 칸 폭을 늘리고 판 확대 버튼 제공.

**10. [초성게임] 자음 타일 글꼴이 영어처럼 보임**

**11. [첫 방문 안내 창] 영어 머리말 + 안 보이는 아이콘**

## 하지 말 것

### [P0-1] 첫 판(공식 답안) 도중 새로고침·앱 종료 → 확인 없이 "공식 0점" 확정
- **화면**: 오늘 탭 → 시험지 게임 플레이
- **재현(직접 확인)**: 오늘 기록 초기화 → 큰 버튼(다음 과목: 네모 그림) → 플레이 중 새로고침. 그러면 `tries.nono=1, best=0`이 되고, 카드는 "공식 0점 · 연습 ♥1"로 바뀝니다. 다시 하려면 하트를 내는 연습 판뿐입니다. 같은 홈의 상단 줄은 "시험지 1/5"인데 "오늘 첫 판 전"이라고 나와 서로 모순됩니다(`scratchpad/ux/reload_home.png`).
- **근거**: `portal/portal.js` 807행 `HOST.beforeStart`는 판을 **시작하는 순간** `d.tries[id]++`를 저장하고, `best`는 끝날 때(`examFinish`)나 "여기서 제출하기"(`quitInfo.onQuit`)에서만 저장합니다. 그 사이에 페이지가 사라지면 진행률 부분 점수(최대 300점)조차 남지 않습니다.
- **사용자 영향**: 전화가 오거나, 카카오톡 인앱 브라우저가 닫히거나, 아래로 당겨 새로고침하는 일은 휴대폰에서 매일 생깁니다. 그때마다 "하루 한 번뿐인 공식 기회"를 잃고, 하트를 써야 다시 할 수 있다고 느낍니다. 서비스의 핵심 약속("첫 판이 공식")이 깨집니다.
- **해결안**
  1. 시작할 때 `d.run = {id, seed, t0, prog}`를 저장하고, 진행할 때마다 `prog`를 갱신합니다. 다시 열었을 때 `run`이 있으면 "이어서 풀기 / 여기까지 제출" 시트를 띄웁니다(이어 풀 수 없는 게임은 진행률 부분 점수로 제출).
  2. 최소한의 대책: `pagehide`/`visibilitychange(hidden)`에서 `quitInfo.onQuit`과 같은 부분 점수 저장을 한 번 실행합니다.
  3. 홈 상단 줄 문구는 `tries`가 아니라 `examDone` 기준으로 맞춥니다(`portal.js` 315행).
- **관련**: `portal/portal.js` `HOST.beforeStart`·`quitInfo`·`renderHome`(315), `core/engine.js` `startGame`. 진행률은 `NG[id]`의 기존 `examProgress` 쪽을 쓰면 되고, core에 게임 이름을 넣을 필요는 없습니다.

## 공통 인터랙션 규칙 제안 (`games/CLAUDE.md` 계약에 추가할 것)

1. **머리 막대**: 왼쪽 = 원형 뒤로(그만하기), 가운데 = 게임 이름 + "모드 · 난이도 · n번째 판", 오른쪽 = `?`. 모든 게임이 `playChromeInit`을 따릅니다(함대·고스톱·동물 삼총사 예외 없음). 소리는 여기 두지 않습니다.
2. **HUD 순서(왼→오)**: `[진행 n/N] [시간] [힌트 n] [보조 1개]`. 칩은 최대 4개입니다. 각 칩 위에 12px 라벨을 둡니다(첫 2판은 필수). 시간이 30초 남으면 칩 색과 숫자 크기로 경고합니다(색만 쓰지 않음).
3. **기회(목숨)**: 공용 한 가지 기호(발바닥 또는 방패)만 씁니다. **하트는 사이트 재화 전용**입니다. HUD 아래 왼쪽에 고정합니다.
4. **판**: 화면 폭 - 32px, 높이는 남은 공간 기준으로 최대화합니다. 누르는 칸은 최소 **28px**(가능하면 36px), 버튼은 **44px**입니다. 판 아래 빈 공간이 120px를 넘으면 판을 키웁니다.
5. **조작 버튼**: 화면 아래쪽 1/3(엄지 영역)에 둡니다. 되돌릴 수 없는 행동(포기, 제출, 두기)은 왼쪽 위나 확인 2단계로 처리하고, 엄지 쪽에는 되돌릴 수 있는 행동(되돌리기, 힌트)을 둡니다.
6. **피드백 시간**: 누름 반응 ≤100ms(눌림 그림자 + 짧은 진동 10ms). 맞음은 초록 + 위로 떠오르는 점수 0.6초. 틀림은 흔들림 3회 0.3초 + 주황 + 기회 1개가 사라지는 애니메이션. 메시지 줄 문구는 1.2~1.6초 뒤 원래대로 돌아갑니다. 쿨다운은 남은 시간 링으로 보입니다. **색만으로 맞음/틀림을 구분하지 않습니다**(✓ / ✕ 모양을 같이 씀).
7. **입력(키보드)**: 입력할 때는 "문제 한 줄 + 입력창 + 확인"을 키보드 바로 위에 붙입니다(`visualViewport`). 엔터 = 확인입니다. 틀려도 입력창은 비우지 않고 전체 선택합니다.
8. **결과 창**: 주 버튼 1개(전체 폭, 맨 아래) + 보조 2개 이하 + 텍스트 링크 1개입니다. 흐름 중이면 승패와 상관없이 주 버튼 = "다음 과목". 하트를 쓰는 행동은 주 버튼이 되지 않습니다. 축포는 글자 뒤에 깔립니다.
9. **뒤로가기**: 모달 → 닫기, 플레이 → 그만하기 확인, 탭 → 오늘 탭, 홈 → 두 번 눌러 나가기.
10. **글자·대비**: 본문 13px 이상, 보조 12px 이상, 대비 4.5:1 이상. 숫자는 `tabular-nums`로 씁니다.
11. **로딩**: 300ms 넘게 걸릴 때만 문구를 보이고, 시계는 판이 다 그려진 다음 시작합니다(지금 방식 유지).

## 하지 말 것
- 하트(재화) 그림을 게임 안 목숨, 친구 응원, 장식에 다시 쓰지 않기.
- 한 화면에 채움색 주 버튼 2개 이상 두지 않기(같은 분홍 남발 금지).
- 연결이 안 됐는데 "찾는 중…" 같은 기다림 연출 보이지 않기, 확인 없이 하트 쓰는 판 자동 시작하지 않기.
- 공식 기회를 쓰는 판(시작 즉시 `tries++`)을 확인 없이 잃게 만들지 않기. 새로고침·뒤로가기·앱 전환을 정상 상황으로 다루기.
- 설명 앞부분에 모든 게임이 같은 문구를 두어 말줄임으로 차이를 지우지 않기.
- 세로 화면에서 아무 안내 없이 판을 90° 돌리지 않기. 특히 연령 확인 같은 법적 화면은 돌리지 않기.
- 10px 글자, 대비 3:1 미만의 노랑/흰 글씨 on 분홍 쓰지 않기.
- 개발용 버튼을 배포 화면에 남기지 않기.
- 꾸밈(축포·배경·캐릭터)이 점수·버튼 글자를 덮거나 누름을 막게 하지 않기(`pointer-events:none`, 글자 뒤 레이어).
- core·embed/shell에 `if(id === '…')` 분기로 위 규칙을 풀지 않기. 게임 정의의 선택 항목(`NG.<id>.hud`, `livesIcon` 등)으로 풉니다.

### P0-1. 가상 숫자가 진짜처럼 보인다 (기부액·참가자 수·상위 %)
- **화면**: 홈 기부 띠 "이번 주 모두의 기부 2,071,309원"(01_home), 리그 "오늘 전 세계 102,765명이 같은 문제를 풀었어요"(02_tab_league), 결과 "같은 문제 푼 사람 중 상위 42.5%"(06_result_win)
- **왜 해로운가**: 세 숫자 모두 시뮬레이션(`prizePool()`, `worldStat()`, 18번 문서 "점수 분포 가정")인데 표시가 없다. 기부액은 **실제로 기부되지 않은 돈을 쌓인 것처럼 보여 주는 것**이라 표시·광고 문제로 번질 수 있고, 들키면 "같은 문제, 공정한 비교"라는 핵심 약속까지 의심받는다. 소수점(42.5%)은 가짜 정밀도라 더 의심스럽다.
- **해결안**
  - 서버 전까지 기부 띠: **"모두의 기부 · 시범 운영 중이에요. 광고 1번에 12원씩, 정식 오픈부터 실제로 쌓여요."** (금액 숫자 숨김) — 또는 금액 옆에 작은 칩 **[예시]**.
  - 참가자 수: 서버 전에는 문구를 빼고 **"전 국민이 오늘 같은 문제를 받았어요"**만.
  - 상위 %: 정수로, 서버 전엔 **"예상 상위 40%"**. 성적 도장(수우미양가)은 유지.
- **관련 파일**: portal/portal.js 149(prizePool)·154(worldStat)·316·363·397·705, 성적 pill(gradePill)

### P0-2. 예시 친구가 "진짜 순위"처럼 결과와 공유에 섞인다
- **화면**: 리그 탭 6명 모두 "예시" 칩(02_tab_league), 결과 창 "지금 친구 7명 중 7위"(06_result_win), 공유 글 "🏆 브론즈 리그 N위"(portal.js 635)
- **왜 해로운가**: 리그 탭은 정직하게 "예시"라고 써 놨지만, 결과 창과 공유 글에서는 예시 표시가 사라진다. 첫 판을 끝낸 신규 사용자가 받는 첫 소식이 **"가짜 친구 7명 중 꼴찌"** 다(예시 친구 점수 1,460~3,820 vs 내 500). 재방문 동기를 깎고, 공유 글을 받은 친구가 "이 사람 친구 리그 1위네" 하고 들어와 보면 가짜다.
- **해결안**
  - 진짜 친구가 0명이면 결과 창 순위 pill을 **"친구를 초대하면 여기서 순위가 나와요 [초대하기]"** 로 바꾼다.
  - 공유 글·카드에서 예시 친구 기반 순위 줄은 뺀다(진짜 친구가 있을 때만).
  - 리그 탭: 예시 칩 6번 대신 상단 안내 한 줄 + 목록 전체를 연하게(불투명도 60%) 처리. 문구: **"아직 친구가 없어서 예시로 보여 드려요. 친구 1명만 초대해도 진짜 리그가 시작돼요."**
- **관련 파일**: portal/portal.js 371·383(리그), 705(결과 순위), 635(공유 글), friends.js(frReal)

### P0-4. 사용자에게 "테스트 도구"가 보인다 · 챕터 배지 "0 / 25"가 틀렸다

### P1-5. 홈 첫 화면에 컨셉이 바로 안 보인다 (정보 과잉)

  4. 기부는 맨 아래 작은 띠로(신뢰 문구 자리, 17번 문서 4절 "신뢰 문구(작게)"와 일치)

### P1-6. "NEW" 배지가 매일 5개 모두 붙는다
- **화면**: 01_home — 시험지 5줄 모두 빨간 NEW
- **왜 해로운가**: 코드상 NEW는 "오늘 아직 안 풂"이라는 뜻(portal.js 328)인데, 사용자는 "새 게임"으로 읽는다. 매일 모든 줄에 붙으니 아무 의미가 없어지고, 정말 새 게임(오늘 추가된 8개)을 알릴 때 쓸 수가 없다.
- **해결안**: 안 푼 줄은 배지 없이 버튼 "시작 무료"만(이미 충분). 푼 줄은 성적 도장(수·우…). **NEW는 "이 사람이 한 번도 안 해 본 게임"에만** — 첫 판 전에 규칙 카드가 뜬다는 신호로 쓴다. 문구 "처음".
- **관련 파일**: portal/portal.js 328

### P1-7. 첫 방문이 일요일이면 첫 시험이 "어려움"이다
- **화면**: 00_first_visit "오늘은 일요일 · 어려움이에요", 홈 전부 "어려움"
- **왜 해로운가**: 요일 난이도는 기존 사용자에게는 좋은 리듬이지만, 신규 사용자는 처음 보는 규칙 + 어려움 + 첫 판이 곧 공식 기록이라 실패 확률이 높다. 첫 결과가 "부분 점수 0점"(07_result_lose)이면 이틀째 오지 않는다. 광고·초대는 주말에 몰린다.
- **해결안(둘 중 대표 결정)**
  - A. **몸풀기 1판(무료·기록 없음)**: 처음 보는 게임이면 시작 전에 "처음이시네요. 쉬운 몸풀기 한 판 먼저 해 볼까요? (무료, 기록 안 됨)" [몸풀기] [바로 시험]. 같은 문제 원칙은 그대로.
  - B. 첫 안내 문구로 기대치 조정: "오늘은 일요일, 가장 어려운 날이에요. 점수가 낮아도 괜찮아요 — 모두 같은 문제라 다들 어려워요."
  - 추천: A + B 문구 둘 다. A는 결정 필요(무료 판이 하나 늘어남).
- **관련 파일**: portal/portal.js 678(첫 안내), quickStart·beforeStart

### P1-8. 결과 창: 할 일이 6개, 실패 창엔 "다음 과목"이 없다
