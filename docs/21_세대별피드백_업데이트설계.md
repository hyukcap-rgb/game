## 1. 회의 결론 한눈에 (12줄)

1. **대전 v3**: 경주형 게임은 최대 5명, 빨리 끝낸 사람이 1위이고 **그 순간 모두 끝**(대표 의견 1). 결과는 "9개 중 7개 · 2위"처럼 실제 진행과 순위로 적고, "실패 · 진행 0%"는 대전 화면에서 없앤다. 순위 = 끝냄 → 찾은(푼) 수 → 틀린 횟수 적은 순.
2. 대전 종류를 넷으로 나눈다: **경주**(먼저 끝내기, 2~5명) · **점수**(정해진 횟수 뒤 점수, 2~5명) · **선점**(한 판을 같이 보고 먼저 누른 사람이 차지, 2~5명) · **차례**(번갈아 두기, 게임 성격대로 2명 또는 2~5명).
3. **같은 상대와 한 판 더**(하트 없이 3판), **친구 방**(방 코드·카톡 링크), 순위×인원 **보상 표**, 연승 불꽃·주간 대전 등급, 대전 공유 카드.
4. **숨은그림·틀린그림·초성·낱말퀴즈는 선점식**으로 바꾼다. 숨은그림은 **그림을 처음부터 다시 그린다**(장면 12개). "다시 대전 = 같은 그림" 버그는 공용(방마다 판 번호를 씨앗에 넣음)과 게임(최근 본 장면 피하기) 두 곳에서 고친다.
5. **짝 잇기**는 대전 목록에 **남긴다**(대표 의견 4): 대전 전용 작은 판 + 상대 판 축소 화면 + 콤보 공격(얼음 덮개).
6. **별빛 구슬**: 속도 2배, 화면 다시 배치, 눈이 편한 블록 모양·색, 대전 = "모든 블록 먼저 없애기", 이벤트 블록 4종(3턴 동안만 반짝).
7. **동물 삼총사**: 효과 강화, 특수 동물 눈에 띄게, 장애물 5종 추가(통나무 칸 등)와 3판부터 장애물이 나오는 새 난이도 곡선, 사람 같은 컴퓨터 속도.
8. **숫자 합치기**: "숫자만 키우기" 대신 **목표 종류 7가지 레벨 설계**, 오늘의 문제는 무작위 입력으로 깰 수 없는 판(무작위 입력 봇으로 점검).
9. **숲 지킴이 삭제**. 오늘의 시험지 '전략' 과목은 숫자 합치기 + **오목(묘수풀이)** 으로(대표 확인 1).
10. **판 고르기·다시 풀기·판 보내기**(대표 요약): 솔로 판 번호를 골라 다시 풀고, 그 판을 친구에게 링크로 보낸다. 지난 7일 오늘의 문제, 방금 한 대전 판도 다시 풀기·보내기.
11. **공용 쉬운 화면**: 도움말 = 그림 1장 + 3줄 + 아래 고정 시작 버튼, 첫 판 손가락 안내, 글자 13px 이상(큰 글씨 설정), 별 조건 판 위 표시, 솔로 1판은 몸풀기 판, 누르고 버튼으로 움직이는 대체 조작, 쉬운 말.
12. **고스톱**: 19세 확인 → 도움말 순서, 방 고르기 화면 세로로, "점당 5,000P" → "큰 판" 같은 이름. 연령 확인 강도·사행성 검토는 개발 범위 밖(대표·법무 확인).

## 2. 회의록 (안건별 세 팀 의견과 합의)

### 안건 1. 대전이 끝나는 규칙과 결과 표기 (대표 의견 1, 중요도 보고 1)

- **기획팀**: 5개 세대가 모두 "상대가 끝나면 내 판이 닫히고 실패 · 진행 0%"를 지적했어요(30대 83초 강제 종료, 50대 1~2개 찾다 닫힘). 보고서는 "내 남은 시간 계속(10초 유예)"을 권했지만 대표 의견은 "빨리 푼 사람이 1등이고 그 순간 종료"예요. 그래서 끝나는 규칙은 지금처럼 두고, **억울함은 표기와 순위로 푼다**: 진행한 만큼 순위를 매기고 실패라는 말을 쓰지 않아요. 결과 뒤 "계속 풀기"(혼자 이어 풀기)는 이미 있으니 그대로 둡니다.
- **UI팀**: 결과 창 맨 위에 "2위"를 크게(40px), 그 아래 "9개 중 7개 · 실수 1번"(17px). 1위는 "다 찾았어요 · 1:42". 끝난 이유는 한 줄로: "판다님이 먼저 다 찾아서 끝났어요". 대전 대기 창의 "실패 · 진행 72%"도 같은 표기로.
- **디자인팀**: 끝나는 순간 화면 가운데에 "판다님이 다 찾았어요!" 띠를 0.7초(지금 알림 시간) 보여 주고, 내 판은 흐려지되 **내가 찾은 것은 그대로 보이게**(흐림 30%, 찾은 표시는 또렷). 진 사람 얼굴은 '아쉬움' 표정, 회색 처리는 하지 않아요.
- **합의**: 대표 의견대로 "먼저 끝내면 모두 종료". 순위 = ① 끝냈는지(끝낸 사람끼리는 끝낸 시각) ② 찾은(푼) 수 ③ 틀린 횟수 적은 순 ④ 마지막으로 하나 찾은 시각이 이른 순 ⑤ 그래도 같으면 공동 순위. "실패" 문구는 대전에서 없앰. 진행 0%로 찍히던 버그(끝나는 순간 진행을 다시 읽어서 생김)는 **잘리기 직전 값을 저장**해서 고침. (결정 190)

### 안건 2. 최대 5명 대전을 어디까지 (대표 의견 2, 중요도 보고 6)

- **기획팀**: 대표 의견은 여우에 대한 것이지만 "누가 먼저 끝내나" 구조인 게임은 모두 같은 규칙으로 5명까지 늘릴 수 있어요. 세대 응답의 "3인 이상 적합" 판정(초성 5/5, 끝말잇기 5/5, 동물 삼총사 5/5, 카드 짝 5/5, 낱말퀴즈·블록·주차 4/5)도 같은 방향이에요.
- **UI팀**: 5명이면 390px에서 지금의 "나/상대 두 줄 막대"가 안 맞아요. 2명은 지금 막대를 키워 쓰고(줄 높이 34px), 3~5명은 **순위 칩 한 줄**(칩 66×52px, 얼굴 28px + 수 18px + 순위 숫자)로 바꿔요. 칩은 실시간으로 순위대로 자리를 바꿉니다.
- **디자인팀**: 5명을 구분하는 **자리 색 5개 + 모양 5개**(색약 대비): 나 = 분홍 원, 2번 = 파랑 네모, 3번 = 주황 세모, 4번 = 초록 마름모, 5번 = 보라 별. 선점식 게임의 동그라미·칠한 칸도 이 색과 모양을 씁니다.
- **합의**: 아래 표대로. 턴제는 게임 성격대로: 오목·함대·고스톱은 2명, 끝말잇기는 2~5명 돌아가며 잇기(막히면 탈락), 카드 짝은 2~4명 번갈아 뒤집기(대표 확인 3). (결정 191)

### 안건 3. 같은 상대 한 판 더 · 친구 방 (중요도 보고 3, 결정 대기 없음)

- **기획팀**: "같은 상대 반복 UI" 평균 1.9점으로 전 항목 최저예요. 결과 창의 "다시 대전 ♥1"은 무작위 새 매칭이에요(portal.js 856줄). 대전 방을 결과 뒤 **30초 동안 열어 두고**, 같은 방에서 다시 시작하면 됩니다. 하트는 첫 판만, **재대결 3판까지 무료**(2·3·4판째), 5판째부터 다시 ♥1.
- **UI팀**: 결과 창 주 버튼 = "같은 상대와 한 판 더 · 무료 2/3"(핑크, 56px). 누르면 버튼이 "판다님 기다리는 중…"으로 바뀌고 상대 쪽 버튼에 "판다님이 한 판 더 원해요!" 배지. 두 사람 이상 누르면 방장이 3초 뒤 시작. 반반 버튼: "새 상대 찾기 ♥1" · "결과 공유". 글자 버튼: "대전 목록 · 홈". 친구 방은 대전 탭 맨 위 "친구와 대전" 카드(방 만들기 / 코드로 들어가기).
- **디자인팀**: 시리즈 점수판(예: "나 2 : 1 판다")을 결과 창 맨 위 작은 띠로. 친구 방 대기 화면은 5자리 자리판(빈자리는 점선 원 + "초대하기").
- **합의**: 3장 계약의 방(room) 구조로 구현. 친구 방 코드는 6글자(친구 서버 코드 글자표 재사용, I·O·0·1 없음), 링크 `?room=코드&g=게임`. 카카오톡 공유는 지금 공유 기능(viralShare·navigator.share)에 링크 글로. (결정 192)

### 안건 4. 보상(순위×인원)과 포인트 쓰임 (대표 의견 2, 중요도 보고 12)

- **기획팀**: 대표 의견 "순위와 참여 인원에 따라 보상 점수가 달라짐". 보고서는 "져도 +150은 쓰임이 없어 이길 이유가 약함". 사람이 많을수록 1위 보상을 키우고, 꼴찌는 100으로 줄입니다(지금 패배 150).
- **UI팀**: 대전 탭 머리에 보상 표 한 줄 요약("2명 1위 +400 · 5명 1위 +550"), 결과 창에서는 내 줄만 크게 숫자 올라가기.
- **디자인팀**: 연승 불꽃은 얼굴 옆 작은 불꽃 + 숫자, 주간 등급은 방패 그림 5단계(새싹·풀잎·나무·숲·별숲).
- **합의**: 아래 표. 공동 순위는 그 순위들 보상의 평균(10 단위 반올림). 컴퓨터 상대(1:1)는 사람보다 적게. 연승 불꽃: 2연승부터 승리마다 +50, 최대 +200(지면 0). 주간 대전 등급: 그 주 대전 포인트 합 0·2,000·6,000·12,000·20,000 → 새싹·풀잎·나무·숲·별숲, 월요일 0시에 새로. 등급은 대전 탭·공유 카드·친구 목록에 보임. (결정 193)

### 안건 5. 숨은그림 · 틀린그림 · 짝 잇기 대전 다시 설계 (대표 의견 4·8·9, 중요도 보고 2)

## 3. 대전 v3 공용 API 계약 (게임 WP와 공용 WP가 동시에 개발하므로 먼저 정함)

### 3-1. 지금 구조(바꾸지 않고 그 위에 얹음)
- `core/net.js`: 방(room)마다 접속자 목록과 각자의 presence(작은 JSON, 8KB까지)를 모두에게 전달. `ROOM.join(name)`, `nr.presence(obj)`(부분 갱신), `nr.peers()`, `nr.onPeers(cb)`, `netNow()`(서버 시각).
- `core/duel.js` v2: 대기실 presence `du:'wait'`·`dg`·`dt`·`nk`로 2명 짝짓기 → 방 `du-<peerA>-<peerB>` → 방장(peer가 작은 쪽)이 `go`(서버 시각)로 동시 시작. 대전 방 presence 키 `pg`(진행 0~1)·`v`/`t`(현재/목표 수)·`lf`(남은 기회)·`dn`(끝남)·`sc`(점수)·`q`(나감)·`go`·`nk`·`nw`·`hb`. 결과는 `duelResolve()` → `HOST.duelResult(r, a, b)`. 한쪽이 끝나면 `duelCutSoon()` → `duelCut()`으로 다른 쪽도 끝, 결과 뒤 `duelContinue()`(계속 풀기).
- 오목·끝말잇기는 같은 방 presence에 자기 키(`om`, `mv`)로 수를 쌓아 주고받고, 함대·고스톱은 `duelLaunch()`로 자기 방(`fl-…`)을 씀.

### 3-2. 서버는 바꾸지 않는다 (이유)
- 다인 방은 지금 서버로 충분: 방 인원 500, presence 8KB, 연결당 방 4개(대기실 + 대전 방 + 여유).
- 사건(공격·선점)은 presence 안의 **사건 기록(로그)** 으로 보냄(3-6). 서버는 내용을 모름.
- 지연: 서버는 이름이 `fl-`로 시작하는 방만 바로 보내고 나머지는 60ms 묶음. 그래서 **v3 대전 방 이름은 `fl-d3-…`** 로 정해 선점 경쟁의 지연을 줄인다(서버 수정 없음). `/stats`는 `fl-` 방을 'matches'로 셈 → 그대로 맞음.
- 위험(받아들임): 판정은 지금처럼 각 기기가 같은 규칙으로 계산(서버 판정 아님). 조작 가능성은 지금 대전과 같은 수준(결정 181).

### 3-3. 버전 섞임 막기
- v2 사이트를 연 사람과 섞이지 않게 v3 대기실 상태값을 새로 쓴다: `du:'w3'`(찾는 중) · `du:'h3'`(방장, 모으는 중) · `du:'j3'`(방에 들어감). v2 코드는 `du === 'wait'`만 보므로 v3를 무시하고, v3는 `'wait'`를 무시한다.
- 대기실 인원 표시(`duelWaiting`)는 `wait`·`w3`·`h3`를 모두 셈.

### 3-4. 짝짓기 흐름 (빠른 대전, 2~5명)
1. 찾기 시작: 대기실 presence `{ du:'w3', dg:게임id, dt:시작 시각(내 시계 ms), nk:별명, dk:'n'|'s'(보통/느긋하게), dv:3 }`.
2. 같은 `dg`·`dk`인 `w3`·`h3` 중 `dt`가 가장 이른 사람이 **방장**. 방장은 방 이름 `R = 'fl-d3-' + 내peer(영숫자 12자) + '-' + dt.toString(36)`을 정하고 `{ du:'h3', dr:R, dc:모인 수 }`.
3. 방장이 아닌 사람은 방장의 `dr`로 `ROOM.join(R)` 하고 대기실은 `{ du:'j3', dr:R }`.
4. 방장이 시작을 정하는 때: 모인 수가 그 게임의 `duelMax` 이거나, 2명 이상 모이고 두 번째 사람이 들어온 지 6초, 또는 찾기 시작 12초. 12초까지 혼자면 **컴퓨터 상대(1:1)**.
5. 방장은 방 presence에 `{ go:서버시각+2500(처음 하는 사람 있으면 +4000), pl:[참가 peer 순서], sd:판 번호 난수(방장이 Math.random으로 만든 8글자, 문제 내용이 아니라 판을 구분하는 표지), r:판 번호, cf:{ dk, av:[피할 것 목록] } }`.
6. `pl`에 없는 늦은 사람은 "이번 판은 꽉 찼어요, 다른 방을 찾을게요" 후 다시 찾기.
7. **문제 씨앗** = `R + ':' + r + ':' + sd`. 같은 방에서 한 판 더 하면 `r`과 `sd`가 바뀌어 **항상 새 판**(지금 v2는 같은 두 사람이 같은 연결로 다시 만나면 `방이름:날짜`가 같아 같은 그림이 나옴 → 이 구조로 고침).

### 3-5. 친구 방 · 같은 방 한 판 더
- 친구 방 이름 `fl-d3-f-<코드6>`. 만든 사람이 방장. 방 presence `cf`에 `{ g:게임id, dk, fr:1 }`. 들어온 사람은 `cf.g` 게임으로 맞춰짐. 방장은 최소 2명이면 [시작]. 방장만 게임·느긋하게를 바꿀 수 있음.
- 링크: 사이트 `?room=코드&g=게임`, 모듈 `embed/<게임>.html?mode=duel&room=코드`(주소 옵션 **추가**).
- 결과 뒤 방을 **30초**(친구 방은 10분) 열어 둠. 각자 `{ ag:r+1 }`(한 판 더 원함)을 올림. 2명 이상 `ag`가 같아지면 방장(남은 사람 중 `pl` 순서가 가장 앞)이 3초 뒤 새 `go`.
- 하트(사이트): 방의 첫 판 ♥1, 같은 방에서 이어진 판은 3판까지 무료(`fr` 카운트는 각자 기기에 `hp:duelFree:<방>`으로), 5판째부터 ♥1. 모듈은 하트 없음.
- 시리즈 기록: 방 안에서 판마다 1위를 센 `sr:{ peer:승수 }`를 각자 계산(같은 규칙이라 같은 값).

### 3-8. 엔진이 게임에 주는 함수 (core/duel.js, 모두 전역)

```js
duelPlayers()        // → [{ pid, seat, nick, me, ai, col, shape, st:{pg,v,t,lf,mis,la,dn,ok,sc,ft}, left, rank }] 자리 순서
duelMe()             // → 내 참가자 객체
duelIsHost()         // → 지금 방장인지(나간 사람 빼고 pl 순서 첫 사람)
duelSend(kind, data) // 사건 보내기 → 번호. kind는 영문 짧은 이름, data는 작은 JSON(200B 이하). 나에게는 다시 오지 않음
duelClaim(key)       // 선점 누르기 → { ok:true(일단 내 것으로 보임) | false(이미 남의 것) }. 확정·뺏김은 onDuelClaim으로
duelOwner(key)       // → 지금 주인 pid 또는 null
duelEndNow(why)      // 선점·차례 게임이 "판 끝"을 알림(모두 같은 상태에서 같은 판단을 하므로 누가 불러도 같음)
duelNotify(text, o)  // 화면 가운데 큰 알림(1.2초, pointer-events:none). o = { from:참가자, kind:'good'|'bad'|'info' }
duelSeed()           // → 이번 판 씨앗 문자열(다시 풀기·판 보내기용)
duelRound()          // → { r, series:{pid:승수}, freeLeft }
duelTurn             // 차례 도우미(3-9)
```

- 자리 색·모양(디자인팀): seat 0 `#F0368A` 원 · 1 `#2F7BFF` 네모 · 2 `#F29E3D` 세모 · 3 `#2BB673` 마름모 · 4 `#8B5CF6` 별. **나는 항상 분홍 원**으로 보이게 내 화면에서만 seat 0과 내 자리를 바꿔 그림(남의 화면에서는 원래 자리 색).

### 3-9. 사건·선점·차례의 규칙(모든 기기가 같은 답을 내는 방법)
- **사건**: 받는 쪽은 사람마다 마지막으로 처리한 번호를 기억하고, 더 큰 번호만 차례로 처리. 40개를 넘게 놓쳤으면(다시 연결) 남은 것만 처리하고 넘어감. 공격 같은 "한 번 일어나는 일"에만 씀(상태는 presence 값으로).
- **선점**: 누르는 순간 `cl[key] = netNow()`를 올리고 내 화면에는 바로 내 색으로 표시(옅게 0.25초 → 진하게). 주인 = 그 키를 누른 사람 중 **서버 시각이 가장 이른 사람**, 같으면 pid가 작은 사람. 나중에 더 이른 기록이 도착하면 주인을 바꾸고 `onDuelClaim(key, owner, { lost:true })` → 게임은 "간발의 차! 판다님이 먼저" 알림과 함께 표시를 바꾸고 내 점수를 되돌림. 받은 쪽은 `cl` 전체를 늘 다시 계산하므로 끊겼다 와도 같은 결과.
  - 선점 확정 시간: 누른 뒤 **0.4초** 동안은 "확인 중"(동그라미 점선). 0.4초 안에 더 이른 기록이 없으면 확정 소리.
- **차례(turn)**: `duelTurn = { order(), cur(), mine(), act(kind, data), onAct(cb), timeout(sec) }`. 차례 순서 = `pl` 순서. 차례인 사람의 사건만 인정(번호 + 차례 번호를 같이 보냄). 차례 시간이 지나고 2초 더 지나면 모든 기기가 같은 "대신 하기"를 계산(씨앗 = 판 씨앗 + 차례 번호)해 진행. 나간 사람 차례는 건너뜀.

### 3-10. 컴퓨터 상대(사람 같은 속도)
- 엔진 기본(`duelAiHuman`): 미리 정한 결과(지금처럼 `duelPace` 평균 시간·성공률)를 **한 칸씩 계단**으로 보여 줌. 첫 진행은 3~6초 뒤, 그다음 간격은 평균 간격의 0.5~1.6배(씨앗 난수), 가끔(15%) 4~8초 멈춤, 틀린 횟수는 0~2번 섞음. 점수 게임은 한 수씩 점수가 오름(한 수 4~8초).
- 표시: 이름 옆 **"컴퓨터"** 꼬리표(지금 'AI'), 찾기 창에서 처음부터 "지금은 컴퓨터와 겨뤄요"(연결 없을 때), 12초 안에 사람이 없을 때 "사람이 없어 컴퓨터와 붙어요".
- 선점 게임의 컴퓨터: 엔진이 계단 시각마다 남은 키 하나를 `duelClaim` 흉내로 차지(같은 씨앗 → 같은 순서).
- 차례 게임 컴퓨터: 지금 게임별 AI 그대로, 생각 시간 1.5~4초.

### 3-11. 결과 계약 (HOST에 넘기는 값, 더하기만)
- `HOST.duelResult(r, a, b, res)`: `r`·`a`·`b`는 지금과 같은 뜻(2명일 때 그대로). **넷째 인자 `res`를 더함**:

```js
res = {
  kind:'race'|'score'|'shared'|'turn', n:인원, ai:컴퓨터 상대인지, pace:'n'|'s',
  rank:내 순위(1부터), tie:공동인지,
  rows:[{ pid, nick, me, ai, col, shape, rank, ok, v, t, mis, sc, ft, left, txt }],  // txt = "9개 중 7개 · 실수 1번"
  why:"판다님이 먼저 다 찾아서 끝났어요",
  round:{ r, series, freeLeft }, room:{ code:친구방 코드|null, canAgain:true|false },
  seed, cfg   // 다시 풀기·판 보내기용
}
```
- 여러 명일 때 `r`: 1위(공동 아님) `'w'`, 1위 공동 `'d'`, 그 밖 `'l'`. 모듈 `finish` 이벤트에는 `rank`, `players`, `kind`, `round`, `room`을 **더함**(기존 `result`·`win`·`vs`·`me`·`opp`·`record` 그대로).
- 순위 비교 기본(경주): ok(다 풂) 먼저 → ok끼리 `ft` 이른 순 → `v` 많은 순 → `mis` 적은 순 → `la` 이른 순 → 공동. 점수: `sc`(끝 점수, 끝 전이면 판 점수) 큰 순 → `mis` 적은 순. 선점: 차지한 수 많은 순 → `mis` 적은 순 → 마지막 차지 시각 이른 순.
- 결과 문구 규칙(대전 화면 전체): "실패" 대신 **"멈춤"**, 진행 % 대신 **"9개 중 7개"**. 1위 = "다 찾았어요 · 1:42"(경주), "4곳 차지"(선점), "2,940점"(점수).

### 3-12. 대전 화면(UI팀 규격, 390×844 기준)
- **2명**: 지금 대전 막대(`#duelBar`)를 키움: 줄 높이 34px, 얼굴 28px, 이름 13px, 값 18px(꼬리표 13px). 맨 위 제목 막대 자리.
- **3~5명**: 순위 칩 줄(높이 60px): 칩 66×52px × 최대 5개, 칩 = 얼굴 28px + 순위 숫자(12px 원 배지) + 값 18px. 순위 바뀌면 0.25초 자리 이동. 내 칩은 분홍 테두리 3px.
- **미니 화면**(짝 잇기·블록·숫자 합치기·별빛 구슬): 칩 줄 대신 72×64px 카드(얼굴 20px + 판 그림 56px). 상대 4명까지 한 줄.
- **큰 알림**(`duelNotify`): 화면 위 30% 지점, 폭 300px, 글자 20px, 얼굴 32px, 1.2초. 같은 사람 알림은 3초에 1번. 판을 가리지 않게 반투명(뒤 판 보임, 배경 85%).
- 대기 창(먼저 끝냈을 때)은 점수·차례 게임에만 남음(경주는 먼저 끝내면 모두 끝이라 필요 없음).

### WP9. 숫자 합치기 (대표 의견 6, 중요도 보고 10)

**고칠 파일**: `games/merge/*`, 새 `tools/random-bot.mjs`(전 게임 점검 도구).

**명세**

| 기호 | 목표 | 예 |
|---|---|---|
| A | 숫자 만들기 | 128 만들기 |
| B | 여러 개 만들기 | 64를 판에 2개 동시에 |
| C | 이동 제한 | 45번 안에 128 |
| D | 얼음 깨기(새 장애물) | 얼음 타일 4개 깨기(옆에서 합칠 때 금 → 두 번이면 깨짐) |
| E | 별 칸 배달(새) | 판의 별 칸에 32 이상 타일 올려 두기 |
| F | 미리 보기 퍼즐(새) | 다음 새 타일 3개가 보임, "12번 안에 정확히 64" 같은 짧은 퍼즐 |
| G | 점수 목표 | 합친 값 합 1,500 이상, 이동 60번 안 |

   - `LAD`·`TUNE`은 새 목표 종류로 다시 만들고 자동 플레이어로 맞춤(목표 첫 도전 성공률 표는 지금 `wantRate` 그대로).
2. **오늘의 문제 공정성**(무작위 입력으로 못 깸): 쉬움 = "40번 안에 64 두 개(B+C)", 보통 = "50번 안에 128, 미리 보기 2개(A+C+F)", 어려움 = "60번 안에 128 + 얼음 2개(A+C+D)". 점수의 효율 기준(par)은 새 판으로 다시.
3. **무작위 입력 봇 점검**(`tools/random-bot.mjs`, 전 게임 공용 도구): 무작위·번갈아 누르기 4종(←→, ↑↓, 시계 방향, 아무거나)으로 오늘의 문제 1,000판(30일 × 난이도) → 숫자 합치기는 **성공률 3% 이하**, 혹시 깨도 점수 400점 이하. 탐욕 봇(가장 큰 합치기 고름)은 60~85%.

5. **화면**: 위 '최고 → 목표' 칸 → 칩 "목표 128"(값 20px) + 칩 "지금 32" + 이동 칩. 판을 화면 높이에 맞춰 키움(아래 빈 195px 없앰). 되돌리기는 판 바로 아래 엄지 자리, 설명 줄 14px 진하게.
6. **효과**: 합칠 때 두 타일이 부딪히며 0.08초 눌림 '쿵', 64 이상 처음 만들 때 그 타일이 커졌다 돌아옴 + 빛 알갱이(지금 256 이상 연출을 64부터, 크기는 숫자에 비례).
7. 도움말 3줄: "밀면 타일이 끝까지 미끄러져요 / 같은 숫자가 부딪히면 합쳐져요 / 목표를 이동 안에 만들면 성공". 4번 카드(솔로 새 규칙) 삭제.

**디자인팀 규격**: 얼음 타일 = 숫자 위 반투명 하늘 `#BFE6FF` 60% + 금 1줄(한 번 맞음). 별 칸 = 판 칸 바닥에 연노랑 별(`#FFE38A`, 50%).

### WP11. 낱말 파티 (초성·끝말잇기·낱말퀴즈)

**고칠 파일**: `games/chosung/*`, `games/wordchain/*`, `games/crossword/*`.

**초성게임**(대표 의견 10)
1. **제시어 정비**: 정답으로 **인정하는 낱말**(지금 사전 그대로)과 **문제로 내는 낱말**을 나눔. 문제에서 빼는 것:
   - 앞붙이 합성어: 왕·꼬마·아기·새끼·물·산·들·참·개·돌 + 원래 낱말(왕개미, 꼬마물떼새, 물방개는 단독 이름이라 예외 판단은 표로).
   - 두 낱말을 붙여 만든 말 중 한 낱말로 굳지 않은 것(예: 장수풍뎅이는 굳은 이름 → 유지, 왕개미·큰고니 → 빼기).
   - 낯선 말(5개 세대 검수표에서 2개 세대 이상 "모름").
   - 방법: 새 목록 `CHOSUNG_ASK_OUT`(빼는 낱말)과 낱말마다 쉬움 표시(`easy` 분류 안에서도 "누구나"/"보통")를 사전 파일 **끝에 더함**(순서를 바꾸면 날짜 씨앗 문제가 바뀌므로). 새 규칙은 **다음 날 0시 날짜부터**(`ASK_FROM`) 적용해 같은 날 문제가 바뀌지 않게.
   - 검수: 1,860낱말을 기획팀이 1차로 표시 → 세대 테스트 그룹(10~50대) 2차 확인 → 확정 표를 CLAUDE.md에 붙임.
2. **선점(버저) 대전**(`duelKind:'shared'`, `duelMax:5`): 8문제, 한 문제를 모두 동시에 보고 **먼저 맞힌 사람이 1점**(`duelClaim('q'+번호)`), 문제당 15초(느긋하게 30초), 맞히는 사람이 나오면 정답과 맞힌 사람 이름을 화면 가운데 크게(1.2초) → 다음 문제. 아무도 못 맞히면 정답 보여 주고 다음. 오답은 0.8초 입력 막힘.
3. **화면**: 문제 카드 크게(폭 358, 초성 글자 56px), 입력창을 키보드 바로 위에 붙임, 위아래 빈 400px 없앰. 상단 칩 '넘기기·힌트' 글씨 13px 이상. 'ㅌ'이 'E'처럼 보이는 글꼴 문제는 결정 188로 고쳤는지 다시 확인.
4. 맞혔을 때 정답이 화면 가득 터지는 연출(1초, 보이기만).
5. 힌트·건너뛰기 버튼 위에 감점 꼬리표("−30", 13px)를 붙여 도움말 없이 알게. 솔로 '분류 ?' 개념 카드 문구를 "분류를 숨겼어요 · 초성만 보고 맞혀요"로.

**끝말잇기**
1. **차례 시간**: 대전 기본 18초(느긋하게 36초), 오늘의 문제 쉬움 20 · 보통 15 → 18 · 어려움 12 → 15, 솔로 빠른 판(번개) 9 → 12초. 남은 시간 5초 이하에서만 칩 깜빡임. 화면 숫자와 실제 시간이 다르던 문제(50대 "15초인데 10초로 보임") 확인·수정.
2. **여럿이 돌아가며**(`duelKind:'turn'`, `duelMax:5`): 3명 이상이면 `duelTurn` 순서대로 잇고, 시간 안에 못 이으면 **탈락**, 마지막 한 명 1위(순위 = 탈락 역순). 2명은 지금 규칙(한방이면 승리, 8개씩 이으면 글자 점수).
3. **쉬운 말**: 한방 → **끝내기 낱말**(규칙·도움말·알림 전부).
4. **화면**: 이은 낱말이 판 위에 기차처럼 쌓임(최근 8개, 위로 밀림), 끝내기 낱말 때 화면 흔들림·폭발 연출. 가운데 흰 카드 크기를 줄여 기록이 보이게. 입력창 안 흐린 글씨 진하게.
5. 대전 준비 화면을 공용 준비 화면으로(30대 "바로 시작해 상대가 누구인지 덜 느껴짐").

**가로세로 낱말퀴즈**
1. **선점(땅따먹기) 대전**(`duelKind:'shared'`, `duelMax:5`): 7×7 판 8낱말, 2분(느긋하게 4분). 누가 먼저 맞히면 그 낱말 칸이 그 사람 색으로 칠해지고 점수(`duelClaim('w'+번호)`). 다른 사람은 그 낱말을 못 넣음(교차 글자는 모두에게 보임 → 힌트가 됨).
2. **단서 보강**: 10대가 모르는 옛날 말(예: 고무줄 놀이)만 있는 판이 안 나오게 낱말마다 세대 표시(모두/30대 이상)를 사전 **끝에 더하고**, 오늘의 문제는 "모두" 낱말이 70% 이상. 요즘 말 낱말 150개 추가(직접 쓴 뜻풀이).
3. **키보드 가림**: 입력 중에는 판을 위로 접고(현재 낱말 줄만 보임) 단서·입력창 크게. 단서 글자 16px, 칸 번호 11px(지금 8px), '가로 1 · 5글자' 꼬리표 13px.
4. 가로·세로 바꾸기: 같은 칸 다시 누르기 + 단서 옆 [가로/세로] 버튼(도움말 없이 알게).
5. 점수 규칙 설명(−20, −40)은 도움말 '더 알아보기'로.
6. 맞히면 그 낱말 칸이 차례로 반짝(0.05초 간격) + 짧은 소리.

**완료 기준**: 초성 제시어 검수표 완성, `CHOSUNG_ASK_OUT` 적용 뒤 오늘의 문제 30일치에 뺀 낱말 0개. 3명 버저·땅따먹기 동시 정답(50ms 차) 주인 같음. 끝말잇기 3명 탈락 순서가 모든 브라우저에서 같음.

### 5-2. 테스트 추가 (`tools/test.mjs`, `tools/duel-test.mjs` 확장)
1. **다인 동시 시작**: 브라우저 2·3·5개로 같은 게임 빠른 대전 → 모두 같은 방, 시작 시각 차 0.3초 이하, 같은 판(판 상태 해시).
2. **첫 완료 종료**: 한 명이 `_solveForTest()`로 끝내면 나머지가 0.4~1.0초 안에 끝, 결과 순위가 모든 브라우저에서 같음, 결과 글에 "실패"·"진행 0%" 없음.
3. **선점 충돌**: 두 브라우저가 같은 키를 50ms 차로 누르게 시간 조작 → 주인이 모두 같고, 진 쪽에 "간발의 차" 알림.
4. **사건 전달**: 짝 잇기 콤보 공격이 받는 쪽 판의 같은 타일에 얼음(해시 비교). 연결 끊었다(3초) 다시 붙어도 같은 결과.
5. **한 판 더**: 같은 방에서 3판 연속 → 씨앗이 매번 다름, 숨은그림·틀린그림 장면이 연달아 같지 않음, 하트는 첫 판만(사이트).
6. **친구 방**: 방 코드로 3명 입장 → 방장 시작 → 방장 나가면 다음 사람이 방장.
7. **느긋하게**: 느긋하게와 보통이 서로 짝지어지지 않음, 느긋하게 판 제한 시간이 2배.
8. **v2·v3 섞임 없음**: 이전 빌드 페이지와 새 빌드 페이지를 같은 서버에 → 짝지어지지 않음.
9. **느린 폰 흉내**(`--stress`): CPU 4배 느리게 + 지연 300ms에서 1~8이 통과.
10. **무작위 입력 봇**(`tools/random-bot.mjs`): 오늘의 문제 30일 × 난이도 3, 게임마다 무작위 입력으로 깨는 비율 → 기준표(아래) 넘으면 실패.
11. **글자 크기 전수**: 각 게임 첫 화면·결과 창에서 보이는 글자 13px 미만 0개, 도움말 [시작하기]가 화면 안.
12. **고스톱 순서**: 첫 진입 화면 DOM에 규칙 창이 19세 확인보다 먼저 없음.
